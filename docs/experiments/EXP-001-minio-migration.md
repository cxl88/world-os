| 项目 | 内容 |

| 投入上限 | 7 天，每天不超过 2 小时（合计 14 小时），额外花费 0 元 |

| 记录 | WORLD OS 独立数据目录 `%USERPROFILE%\worldos-exp001`；第 7 天的结论写进 #12 |

## 1. 已知事实与尚未核实的假设

**已知事实**（Claude 于 2026-10-23 读原文并摘要，**还没有经过你人工核实**，见 #11）

| # | 事实 | 来源 |
|---|---|---|
| F1 | 2025 年 MinIO 社区版控制台只剩对象浏览，账户、策略、配置等管理要用 `mc` 命令行或付费的 AIStor | #9 Blocks & Files，2025-06-19 |
| F2 | 2025-12 社区版进入维护模式：不再接受新功能和 PR，安全修复按个案评估；报道列出的替代品有 SeaweedFS、Garage、RustFS，并称还没有社区分支获得足够关注 | #10 InfoQ，2025-12-28 |
| F3 | RAGFlow 社区有人提议替换默认的 MinIO，维护者回复主要难点是迁移工具，并征集贡献者 | #16 GitHub Issue，页面未显示开帖日期 |
| F4 | 软件停止维护后，多数组织没有能力自己打补丁；未通过合规审计的组织中 55% 在运行停止维护的软件。来源是卖支持服务的厂商，有立场偏差 | #4 OpenLogic，2026-03-31 |

F1 和 F2 都是在报道 MinIO 自己的变化，核实时要看它们是否引用同一个源头（同源只算一个来源）。

**尚未核实的假设**（本实验要验证或证伪的）

| # | 假设 | 怎么验证 |
|---|---|---|
| H1 | 有相当数量的中小团队在生产环境用 MinIO 社区版 | 第 1–2 天公开研究：讨论帖、默认用 MinIO 的项目、招聘要求 |
| H2 | 他们把维护模式当成需要在 3–6 个月内处理的风险 | 访谈第 2、3 题：问他们已经做了什么，不问打算 |

| H4 | 有人愿意为评估或迁移付钱，而不是自己做、买 AIStor 或上云 | 访谈第 6–9 题。只有具体的价格、预算数字或定金才算付费信号 |
| H5 | 真正的难点在策略、账户、版本、应用配置，而不是复制数据 | 第 3–4 天隔离环境测试 |
| H6 | 替代品还没有成熟的免费一键迁移方案 | 第 1–2 天查替代品文档和 Issue |
| H7 | 其他把 MinIO 作为默认组件的开源项目，下游用户有同样的需求 | 第 1–2 天公开研究（下面列出的项目是凭记忆，需要逐个打开确认） |

**付费意愿目前没有任何证据**，系统里“支付意愿”一项最多只能给 2 分。

只读公开内容，不登录别人的系统，不收集个人隐私。每找到一条有用的，用 `item-add` 记下链接和日期。

|---|---|---|

## 3. 最小迁移评估方案（交付物是一份评估，不是工具）

给潜在客户的是一份 1–2 页的评估。第 2 天写好模板，第 4 天用测试结果补全。

1. **现状清单**（请对方提供，不要求任何访问权限）：MinIO 版本和发布日期；单机还是分布式、纠删码配置；数据量、对象数、桶数、最大对象；是否用到版本控制、对象锁、生命周期、复制、事件通知、服务端加密；账户和策略数量；哪些应用和 SDK 在连；是否用预签名链接；能接受多长停机。
2. **风险判断**：是否暴露在公网，数据敏感程度，用到的哪些功能在替代品里可能缺失（待第 4 天的测试确认）。
3. **方案对比**：
   - 继续用旧版：固定版本，做网络隔离；
   - 买 AIStor；
   - 迁到云对象存储；
   - 迁到自托管替代品（SeaweedFS、Garage、RustFS、Ceph）。

   每种写清优缺点和“待验证”项。
4. **迁移做法**：用现成开源工具复制（如 rclone、`mc mirror`），切换方式（停机窗口、双写、读回退），校验方法（对象数、总字节、逐个对象的内容哈希），回滚方案。
5. **工作量与报价**：用第 6 节的模板。

## 4. 隔离测试环境验证设计（第 3–4 天，不超过 6 小时）

**边界**：只在你自己的电脑上用 Docker 跑，只用自己生成的合成数据；不连接任何客户或第三方环境，不使用真实业务数据。

| 项目 | 设计 |
|---|---|
| 源 | MinIO 社区版容器，固定一个版本标签并记下来 |
| 目标 | 只选一个替代品（SeaweedFS、Garage、RustFS 三选一），也是固定版本 |
| 合成数据 | 约 1 万个对象，总量 2–5 GB；大小从 1 KB 到 10 MB 不等，外加几个超过 100 MB 的分段上传对象；多级前缀；**中文和空格文件名**；自定义元数据；一个开启版本控制的桶；一条桶策略；一个只读账户 |
| 复制 | 用 rclone 或 `mc mirror`。具体参数以工具官方文档为准，先在 100 个对象上试跑 |
| 校验 | 对象数、总字节、逐个对象内容哈希（分段上传的 ETag 和普通对象不同，不能直接比 ETag）、元数据、中文文件名 |
| 兼容性 | 用一个 S3 SDK 小脚本在目标上测：列举、分段上传、预签名链接、删除 |
| 记录 | 每一步的实际耗时、失败和需要手工处理的项（账户、策略、版本、生命周期通常不会随数据一起复制，要逐项确认） |

产出：一份“哪些能自动迁、哪些要手工处理、花了多久”的记录，直接用来补全第 3 节的评估模板和第 6 节的工时。

## 5. 访谈问题

**谁来联系、怎么联系，由你决定并亲自做。** 优先联系在公开渠道讨论过迁移的人，在原帖下回复或用他们公开的联系方式；遵守社区规则，不群发。开场说明你是谁、为什么问、只记录代号。

1. 你们现在怎么用 MinIO？版本、数据量、几个环境，是不是生产？
2. 2025 年控制台功能被移除、12 月进入维护模式之后，你们**实际做了什么**？
3. 这件事在你们这个季度的待办里排第几？最担心的是什么？
4. 评估过替代方案吗？卡在哪一步？已经花了多少人天？
5. 如果要迁，谁来做，谁拍板，有没有预算？
6. 过去为类似的运维或迁移工作付过钱吗？付给谁，大概多少？
7. 如果下个月必须完成，你们最可能怎么做：自己做、买 AIStor、上云，还是请人？
8. 我可以根据你们愿意分享的非敏感信息，免费做一份 1 页评估。你们愿意花 30 分钟看结果吗？
9. （只在第 8 题得到肯定后问）如果评估之后由我做迁移实施，报价是 ____ 元（说一个具体数字），你们会考虑吗？需要什么条件？
10. 还有谁也在为这件事头疼？方便介绍吗？

记录规则：
- 只记对方的原话和已经发生的事，用 `log interview --who 代号 --claim "原话"`。
- “听起来不错”不算付费意愿。只有对方接受具体价格、给出预算数字和时间，或者付了定金，才能记成 `log quote` 或 `log intent`。
- 不记真实姓名、公司名以外的隐私信息；对方要求不记录的，不记。

## 7. 第 7 天的决策规则

先在系统里数清楚以下数字，只数已经用 `log` 记录、带对方代号的：

| 指标 | 含义 |
|---|---|
| 联系数 N | 实际联系并得到回复的团队数（目标 ≥ 10） |
| 确认需求数 D | 明确说 3 个月内要迁移或替换 MinIO 的团队数 |
| 付费信号数 P | 接受具体价格、给出预算数字和时间、或付定金的团队数 |
| 免费方案 | 是否发现替代品已有成熟的免费一键迁移方案（是 / 否，附链接） |
| 实际工时 | 是否超过 14 小时（超过 21 小时即暂停） |

| 结论 | 条件 | 接下来 |
|---|---|---|
| **继续** | D ≥ 2 且 P ≥ 1 | 先交付这 1 份付费（或付了定金的）评估或迁移；只有交付需要时才开发工具 |
| **调整** | D ≥ 2 但 P = 0 | 改报价或交付形式（比如固定价格的评估），或者换一个客户群；最多再做一轮 7 天。如果只有人要免费工具，就把它降级为开源贡献或人脉积累，不再算收入机会 |
| **暂停** | 找不到 10 个可联系的团队，或 D < 2，或已有成熟的免费一键迁移方案，或工时超过 21 小时 | 暂停这张卡，写明原因 |

不允许为了“继续”而把模糊的表态记成付费信号。

## 8. 每天做什么，系统里怎么记

**第 0 天（准备，约 20 分钟）**

```powershell
cd "$HOME\world-os"
$env:WORLDOS_HOME = "$HOME\worldos-exp001"     # 独立数据目录；每次打开新窗口都要先执行这一行
python -m worldos init
python -m worldos item-import examples\bug_hunter_2026-10\items.json
$ids = python -m worldos --porcelain cards-import examples\bug_hunter_2026-10\ai_output_batch2.json --ai --items "4,9,10,14,15,16"
$card = @($ids)[0]
python -m worldos card $card                   # 确认是“MinIO 社区版停更后的迁移缺口”，记下卡号
python -m worldos review $card --reason "Experiment 001 开始前人工审核"
python -m worldos status $card researching
$gov = @($ids)[1]                              # 同一批导入的“政府运维采购”卡，样本报告结论是暂不参与
python -m worldos review $gov --reason "已阅"
python -m worldos status $gov paused --reason "需要公司主体与业绩，且禁止转包分包（BUG_HUNTER_SAMPLE）"
$due = (Get-Date).AddDays(7).ToString("yyyy-MM-dd")
$act = python -m worldos --porcelain action-add $card --title "Experiment 001：MinIO 迁移需求 7 天验证" --hypothesis "至少 2 个团队 3 个月内要迁移，至少 1 个愿为评估或迁移付费" --acceptance "按 EXP-001 第 7 节决策规则" --due $due --minutes 840 --money 0
"卡号 $card，行动号 $act"                       # 记下来，之后的命令要用
```

**第 1–2 天：核实来源（#11）和公开研究**

```powershell
python -m worldos card $card                   # 看证据编号
python -m worldos evidence-verify <证据编号> --type public      # 对过原文的才核实；同源只核实一条
python -m worldos score $card --pain 2 --access 3 --feasibility 4 --reuse 3 --risk 3 --basis "<核实了哪几条公开资料；还没有客户证据>"   # 分数按你的判断填；评分后简报才会推荐这张卡
python -m worldos item-add --title "<帖子标题>" --source "GitHub" --url "<链接>" --published <日期>
python -m worldos log time --category research --minutes 60
```

**第 3–4 天：隔离测试（第 4 节）**

```powershell
python -m worldos log time --category build --minutes 120
python -m worldos log insight --card $card --note "测试结论：……"
```

**第 5–6 天：联系与访谈（第 5 节）**

```powershell

```

**第 7 天：决策**

```powershell

python -m worldos brief
python -m worldos action-done $act --result "联系 N 个，确认需求 D 个，付费信号 P 个；……" --decision continue    # 或 adjust / pause
python -m worldos score $card --pain 2 --access 3 --feasibility 4 --reuse 3 --risk 3 --basis "<依据>" --reason "Experiment 001 第 7 天"   # 分数按实际证据填，这里只是格式示例

```
